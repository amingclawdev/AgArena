# Team discussion

The items below are open questions, not implementation requirements.

## Hackathon scope

- Which farmers, crops, and geographic region should the demo serve?
- What problem should the demo solve first?
- What is the smallest complete user journey we can demonstrate?
- What are the deadline, judging criteria, and team roles?

## Forecasts

- Which weather conditions and forecast horizon matter most?
- Which weather provider should we use, and what are its access and usage limits?
- How should the app communicate uncertainty or unavailable data?

## Farmer notifications

- Which events should trigger an alert?
- How should thresholds be chosen or configured?
- Which notification channel should the demo support?
- Do notifications need to work when the app is closed?

## Map and farm area

- How should a farmer select or enter a location?
- Should areas be represented by points, circles, or field boundaries?
- Should the map show a farm, forecast coverage, or an affected weather area?

## Implementation

- Agree on the platform, technology stack, and hosting.
- Decide what data needs to be stored and how it should be protected.
- Split the agreed work into issues with owners and acceptance criteria.
